Browser page Find regression boundary

The Telegram-styled search row uses the existing TGUIKit SearchView with themed controls, localized accessibility labels, Return/Shift-Return and Cmd-G/Shift-Cmd-G navigation, and Escape dismissal. WebAppUI already depends on InstantPageUI; the shared feature-specific bar lives there, not in a hub or a new cross-screen dependency.

On macOS11 and later, mini-apps and TON sites use public WKWebView.find, which reports matchFound but not the number or ordinal of matches. The web row therefore provides next/previous and no-result feedback without inventing a count. A serialized latest-query queue suppresses stale result callbacks and ensures an in-flight search is followed by the clear request after dismissal. Old macOS10.15.4-10.15 deployments retain the existing native NSTextFinder fallback; no deployment target is raised. No private search API, global pasteboard changes, JavaScript injection or DOM rewriting.

Native Instant View reuses the previously verified segmented text/geometry/visibility mapping. Matching is local, literal and case-insensitive; each segment is a search boundary. Unrevealed spoilers, attachments, undrawn truncated glyphs and collapsed detail bodies are excluded. Expanded/offscreen text remains indexed; scrolling resolves its live geometry. The row displays actual current/total results; viewport-limited overlays use theme colors and are excluded from input and accessibility. They do not modify article selection or expand details.

Run with python3 -I tools/tests/browser-page-find/run.py --output /absolute/new-directory --lock /absolute/shared-compiler.lock.

The portable runner compiles the exact production BrowserPageFind and BrowserFindRequestQueue with controlled WebKit/KVO and search-bar boundaries, using real AppKit geometry/action enums. It covers modifier routing, geometry, active webview attachment, show/navigation/hide, retarget, reload/navigation invalidation and observation disposal. It does not load a webpage. BrowserFindRequestQueueTests.swift additionally tests asynchronous query ordering, stale result suppression, close while in-flight, owner release and direction preservation using real production queue code.

Source wiring checks are separate from runtime checks. Complete real InstantPageUI and WebAppUI module compilation against real dependencies is recorded independently; portable runner success alone is not a full SDK/UI integration pass. Native text/geometry/matching tests live in packages/InstantPageUI/Tests/InstantPageUITests/InstantPageTextFinderTests.swift.

No live GUI, VoiceOver, mini-app/site loading, account/profile/database, payment, Contacts or Keychain access. Visual/native focus acceptance belongs to the user. Ordinary HTTPS links remain external. Existing fullscreen-space behavior is not silently changed.
