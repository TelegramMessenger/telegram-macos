U19 ordinary attachment individual spoilers native regression harness

Run with python3 -I tools/tests/attachment-individual-spoilers/run.py --source-root PATH --output PATH --compiler-lock PATH.
The optional lock defaults to OUTPUT/compiler.lock; concurrent native builds must pass a common --compiler-lock explicitly. Output and lock paths must be outside both source and harness repositories, checked before creating directories. The script rejects non-isolated Python, acquires an exclusive fcntl.flock before every swiftc invocation, uses -j1, and releases the lock before executing the synthetic fixture. No app is launched. The compiler target is the host architecture at macOS 13.0 with the installed SDK, avoiding a default host target unsupported by the installed standard library.

Use --baseline for the negative control. It reads exact commit 14a0ffe4d100136d4afdaa43a797d32699cb23f3 from the harness repository, not the HEAD of --source-root. Missing files in a sparse source root also come from that pinned object. --core-git-dir can override the pinned telegram-ios object store, otherwise it is resolved from the harness repository common Git directory. The MediaSpoilerMessageAttribute class is extracted from core commit 24638bc69bd083981b178dd1e7f921eebbf7fc46. Input origins and SHA256 values, extracted block hashes and fixture hash are recorded in extraction.json.

What actually compiles and executes
- PreviewSendingState, including per-URL overrides and all copy/update methods.
- PreviewEntry IDs, entry construction/equality, per-album URL slicing and actual row item construction.
- Complete MediaPreviewRowItem and MediaGroupPreviewRowItem classes, including actual menu handlers, spoiler layout parameters and single-row accessibility action construction.
- Album mouseUp reorder implementation, with immediate redraw contents inspected.
- Controller URL setter, editor URL replacement helper, global spoiler menu, argument callbacks for toggle/delete/reorder, interactive normalization closure and prepared-state comparison closure.
- Controller spoiler snapshot, paid-media wrapping closure and complete grouped/ungrouped send branch. Paid wrapping is compiled but never invoked by a test.
- ChatInteraction sendMedias declarations and sendMediasObserved forwarding method.
- Exact ChatUI and StoriesUI sender closure signatures and actual Sender.enqueue call expressions, including observed callbacks. Surrounding permissions, scheduling windows and analytics lifecycles are not executed.
- Both full Sender.enqueue(media: [Media], caption: ...) overloads, including attribute creation, per-message binding, grouping, captions and additional-text assembly.
- Pinned core MediaSpoilerMessageAttribute class, with Postbox protocol/encoder/decoder scaffolding only.
- Pinned Array.move/chunks implementations.
- All seven production files are also parsed by swiftc -parse. Parse success is not package typechecking.

Fixture substitutions
Visibility modifiers are removed in extracted blocks solely to permit inspection from one Swift fixture file. No behavior is rewritten in those blocks. Foundation and CoreGraphics are native. Telegram media, account context, Postbox protocol, signal plumbing, analytics, table/view classes, layout and localization are small explicit fixture types, not real application modules. GroupedLayout has deterministic vertical tiles and a requested move target; it does not test the production collage layout algorithm. Signal execution and account enqueue are synchronous in-memory capture. URL strings are synthetic and never read from disk. Strings and icon payloads are fixtures; production source references existing strings() and MenuAnimation. NSAccessibilityCustomAction is a callback fixture, not a live accessibility tree.

The baseline has no replacement helper, so the harness wraps its exact existing self.urls[index] = new assignment with the same test-facing signature. It supplies a constant true prepared-state closure because the baseline has no prepared-state equality gate. Missing individual menus are inherited empty methods of the row superclass; the harness does not invent a baseline toggle. Invalid table indices are invoked only when the source includes the new guard, otherwise that guard assertion fails without crashing the negative control. Source-wiring checks count the three editor helper call sites and check the send guard/transition assignment strings separately from runtime assertions. They are not claimed as editor or queue integration tests.

Coverage
Grouped and ungrouped photo/video/GIF actions, independent on/off, global all-on/all-off and mixed global-default exclusions, send-as-spoiler true and explicit false without state mutation, all existing Bool enqueue calls, URL identity despite equal basenames, reordered/deleted/edited URLs, image/paint/video helper wiring, same-URL replacement, delete then re-add, explicit false override migration, 23 attachments split 10/10/3, separate grouping keys, batch-local indices, ChatUI/StoriesUI transport, caption position and silent/schedule/effect attributes, independent additional text, file-mode gating, excluded round video/sticker/document eligibility, stale table/menu targets and invalid indices. Album constructor asserts messages.count == urls.count == spoilers.count; the sole production constructor call comes from aligned ten-item slices. Normalized initial/media/file/archive/collage state is authored before publication; preparation changes media only.

Not established
No full SwiftPM or Xcode graph build, real TelegramCore type integration, live AppKit event delivery/menu rendering, visual spoiler animation, live accessibility behavior, asynchronous queue timing under load, media decoding/editor rendering, filesystem replacement collisions, network/server acceptance, account/database/keychain access, payment interaction or secret-chat interaction. The three real editor result callbacks are source-wiring checked, not opened. No actual payment or secret-chat actions execute. A full application build is a separate check; manual acceptance belongs to the user.

Known integration boundaries
The publication base includes merged PR330 and PR331. Its message-ID album URL mapping, URL-based reorder callback and immediate URL/parameter alignment are retained; the caption-close confirmation is unchanged. The existing preview-album-target harness is adapted for the spoiler-array constructor, optional toggle callback, captured edit URL and captured table URL list; its assertions remain unchanged and it still supports the upstream source shape. Album-row table resort is disabled because its indices are albums, not attachments; per-tile reorder remains. Ungrouped table reorder captures the displayed URL snapshot so a later deletion cannot retarget the drop. The harness extracts either baseline or fixed table closure without rewriting its capture list. PR333 grouping preference and PR274 multi-album caption behavior are intentionally untouched. Existing per-album caption behavior is not claimed fixed. The legacy sendMedias fallback is still Bool-only, but all production attachment preview consumers (ChatUI and StoriesUI) install the extended sendMediasWithAnalytics path; no new cross-screen dependency is introduced.
